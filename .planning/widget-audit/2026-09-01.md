### Instrumentation (prerequisite for data-driven future audits)

No widget-level hit data exists. Until instrumentation is in place, every future audit will be structural (like this one) rather than usage-driven. Recommended minimal patch:

**Option A — Log to `audit_trail`** (zero schema change):

Add this call at the top of each standalone widget API route handler (after auth check):

```typescript
// In each /api/dashboard/<widget>/route.ts
import { logAudit } from "@/lib/audit";

// After auth check, fire-and-forget:
logAudit(supabase, {
  entityType: "widget",         // new entity type string — valid as VARCHAR(50)
  entityId: "00000000-0000-0000-0000-000000000000", // sentinel UUID (no real entity)
  action: "widget_view",
  performedBy: dbUser.id,
  changes: { widget: { old: null, new: "<widget-id>" } },
}).catch(() => {});
```

Query to count hits over last 30 days:
```sql
SELECT
  changes->>'widget'->'new' AS widget_id,
  COUNT(*) AS hits,
  COUNT(DISTINCT performed_by) AS unique_users
FROM audit_trail
WHERE entity_type = 'widget'
  AND action = 'widget_view'
  AND created_at >= NOW() - INTERVAL '30 days'
GROUP BY 1
ORDER BY 2 DESC;
```

**Option B — Dedicated `widget_views` table** (cleaner, more queryable):

```sql
-- Migration: NNNNN_widget_views.sql
CREATE TABLE widget_views (
  id          BIGSERIAL PRIMARY KEY,
  widget_id   TEXT NOT NULL,
  user_id     UUID REFERENCES users(id) ON DELETE SET NULL,
  location_id UUID REFERENCES locations(id) ON DELETE SET NULL,
  viewed_at   TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_widget_views_widget ON widget_views(widget_id, viewed_at DESC);
ALTER TABLE widget_views ENABLE ROW LEVEL SECURITY;
CREATE POLICY "admin_read" ON widget_views FOR SELECT USING (
  EXISTS (SELECT 1 FROM users WHERE auth_id = auth.uid() AND role IN ('admin', 'manager'))
);
CREATE POLICY "auth_insert" ON widget_views FOR INSERT WITH CHECK (auth.uid() IS NOT NULL);
```

Option B is preferred if the team wants per-location breakdowns or richer slice-and-dice. Option A is lower friction and zero schema change — good for a quick first pass.
