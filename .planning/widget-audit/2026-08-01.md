## Action Items

1. **Delete the three dead widgets** (`recent_activities`, `notes`, `support_summary`): remove their component files, delete their entries from the `renderWidget` switch in `dashboard/page.tsx`, remove their IDs from `WidgetId` and `WIDGET_REGISTRY` in `dashboard-config.ts`, and delete `src/app/api/dashboard/support/route.ts`. These save one unnecessary DB query per dashboard load for every accounts/fms/office_admin user.

2. **Add widget-view instrumentation** before the next audit cycle. Recommended minimal approach: in each `/api/dashboard/*` route handler, add a fire-and-forget `audit_trail` insert with `entity_type = 'dashboard'` and `action = 'widget_view'`, including the widget slug and requesting user ID. Alternatively, create a dedicated lightweight table:

   ```sql
   -- Migration: NNNNN_widget_views.sql
   CREATE TABLE widget_views (
     id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     widget_id   text NOT NULL,
     user_id     uuid REFERENCES users(id) ON DELETE SET NULL,
     role        text,
     viewed_at   timestamptz NOT NULL DEFAULT now()
   );
   ALTER TABLE widget_views ENABLE ROW LEVEL SECURITY;
   CREATE POLICY "Admins read widget_views"
     ON widget_views FOR SELECT TO authenticated USING (
       EXISTS (SELECT 1 FROM users WHERE auth_id = auth.uid() AND role = 'admin')
     );
   CREATE POLICY "Service insert widget_views"
     ON widget_views FOR INSERT TO authenticated WITH CHECK (true);
   CREATE INDEX idx_widget_views_widget_viewed ON widget_views(widget_id, viewed_at DESC);
   ```

   Then in each API route (example for `/api/dashboard/cash-aging/route.ts`):
   ```ts
   // fire-and-forget, never awaited
   supabase.from('widget_views').insert({ widget_id: 'cash_aging', user_id: session.user.id, role: userRole }).then(() => {});
   ```
